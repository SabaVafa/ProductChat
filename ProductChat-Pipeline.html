ProductChat · Retrieval-Augmented Generation

How ProductChat answers a question

The heavy work of turning 1,474 products into searchable vectors happens once, ahead of time. Each live question then needs only a cheap embed, a filtered vector search, and one grounded answer — so replies are fast and can only talk about real catalog products.

  • App — local logic, free
  • Mistral — paid API call
  • Qdrant — local vector DB, free

Preparation

offline · periodic

Runs on indexing / sync — not when a shopper asks. Builds and maintains the vector index everything else reads from.

  1. 01Appscraper.py → SQLite

    Scrape the catalog

    Read the sitemap, fetch each product page, pull structured data (name, price, image, category) into the database. Change-detection means only new or changed products get re-processed.

  2. 02Appimport/jtl · dedupe

    Enrich & dedupe

    Fold in JTL variant attributes (Farbe, Montageart, Material) and merge records that share a product URL, so one SKU is one row.

  3. 03Mistral → Qdrantindexing.py · mistral-embed

    Embed & store — the batch job

    Turn each product's text into a 1024-number vector (batches of 5), and upsert it into Qdrant with a payload (name, price, category). The expensive step — hundreds of calls, minutes, rate-limit prone.

  4. 04Qdrantbestsellers.py · gravur.py

    Attach signals — no re-embed

    Patch bestseller_rank and the gravur tag straight onto the stored points. Meaning didn't change, so no Mistral call — just cheap payload updates.

  5. 05Mistralsuggestions.py

    Generate starter chips

    Pre-write the native-German starter questions — one per product family — and cache them, so no LLM call is needed per chat.

  6. 06Appindexing.reconcile

    Reconcile

    Diff the database against Qdrant and re-flag any product that's silently missing from the index — turning silent index-loss into a visible, self-closing gap.

Qdrant now holds the index

1,474 product vectors + payloads, sitting on disk — ready to be searched. Phase 2 reads from here and never rebuilds it.

Answering

live · per question

Runs on every message — about three Mistral calls total: understand, embed, generate.

  1. 01Appguardrails.py · limiter.py

    Guardrail & rate limit

    Reject prompt-injection and abuse; cap at 30 requests/min before any model is touched.

  2. 02Mistralquery_understanding.py · small

    Understand the query

    Turn the message + recent context into a structured query: categories (family-expanded), search_text, price bounds, gravur. Where "ohne Gravur", "cheaper", and topic-switches get resolved.

  3. 03Mistralembeddings.py · mistral-embed

    Embed the search text

    Convert the cleaned search phrase into a query vector — the one small, cheap embed per question.

  4. 04Qdrantqdrant_service.search

    Filtered vector search

    Find the product vectors nearest the query — with category, price, and gravur filters applied inside Qdrant. Reads the index built in Phase 1.

  5. 05App_apply_negation_filter · tie-break

    Refine the candidate set

    Drop products that headline an excluded feature ("ohne X"), then nudge genuine bestsellers up among comparably-relevant picks — never over a clearly better match.

  6. 06Appmistral.py · prompt

    Build the grounded prompt

    Assemble system rules (German du-Form, EUR, never invent products), shop facts, and the retrieved products as the only context the model may use.

  7. 07Mistralgenerate · medium

    Generate the answer

    The LLM writes the recommendation using only the retrieved products — the "augmented generation". Grounding is why it can't invent products that don't exist.

  8. 08App_order_recommendations

    Post-process into cards

    Map the picks back to real records, add flags (popular, has_variants), drop any hallucinated IDs, and build the refine chips.

  9. 09Appwidget

    Return to the widget

    Answer text + product cards + refine chips render in the chat — grounded, in German, priced in €.

The one-line model

Offline — turn every product into a searchable vector, once.

Live — turn the question into a vector, let Qdrant fetch the closest real products, then let Mistral write an answer allowed to talk only about those.
