ProductChat · Reference

Glossary

Plain-language definitions for the terms in the request-flow diagram (productchat-flow.html). Each entry describes the term as it is used in this system, not just in the abstract.

The models (all Mistral, three different jobs)

mistral-small
A smaller, cheaper LLM used only to parse the question into structured fields. Fast; it doesn't need to be brilliant.
mistral-embed
An embedding model: it turns text into a vector (see below). Not a chat model.
mistral-large
The strong chat model that writes the final answer and chooses which products to recommend.

Retrieval concepts (the "search")

Embed / embedding
Converting text into a list of numbers (a vector) that captures its meaning, so similar meanings land near each other.
query vector · 1024-dim
The question's embedding: a list of 1024 numbers. "Dimensions" = how many numbers; more = more nuance.
Vector search
Instead of matching keywords, find the catalog vectors closest to the query vector. This is how "letterbox" can match a product titled "Briefkasten."
cosine / top-N cosine
Cosine similarity measures the angle between two vectors (1.0 = identical direction, 0 = unrelated). "top-N" = return the N closest.
Qdrant
The vector database: stores all product vectors and finds the nearest ones fast.
category + price filters
Hard constraints applied during the search (only Briefkästen, only ≤ €150), so relevance can't override them.

Ranking

Bestseller tie-break
A small nudge that lets popular products lead when results are otherwise similarly relevant.
relevance-gated
The nudge only applies inside a relevance tier; it never promotes an off-topic product.
banded
Popularity is bucketed into coarse bands (top-5 / top-15 / …) rather than used as an exact number.

LLM output

intent
The structured result of understanding the question: {categories, price_min/max, search_text}.
picks + reasons
The products the LLM chose, each with a one-line justification.
hallucinated ids
Product IDs the LLM invents that aren't real; the system detects and drops them.

The two stores (they do different things)

Qdrant
Vector database; holds the embeddings plus bestseller_rank in each product's payload (extra metadata attached to a vector).
SQLite
An ordinary file-based relational database; holds the product records and the ops journal (an audit log of every pipeline run).

Background jobs

Scraper sync
Periodically reads the shop's sitemap (a machine-readable list of all pages), fetches changed products, and upserts them ("update or insert") into Qdrant.
?Sortierung=11
The URL parameter that sorts a shop category by "Bestseller"; the capture job crawls those pages to learn each product's rank.
set_payload
A Qdrant operation that writes just the metadata (the rank) onto existing vectors without re-embedding them.

Plumbing & arrows

POST /api/chat · rate-limited 30/min
The HTTP request the chat widget sends; at most 30 calls a minute per user (an abuse guard).
RAG
Retrieval-Augmented Generation: retrieve real data first, then let the LLM generate an answer grounded in it — so it recommends actual products instead of made-up ones.
store read / store write
Solid muted arrow = the request reading from a database; dashed arrow = something writing to one (a background job, or the run/feedback write-back).
👍 / 👎 feedback
After the answer, the customer's thumbs-up/down is written back to SQLite, alongside the operations-journal record of the run.
